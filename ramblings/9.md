# A love story (feat. @rpc and MY SHOTGUN)
I've been learning more and more about the multiplayer API and I'm going to start jotting down my notes here.

The arguments for defining an RPC have always confused me so I decided to research them a bit more:
```gdscript
@rpc(
    mode: String = "authority",
    sync: String = "call_remote",
    transfer_mode: String = "unreliable",
    transfer_channel: int = 0,
)
```

`mode` defines who is allowed to *call* the function tied to the RPC. It isn't who *sends* the RPC, like how I thought originally. Options:
- *"authority"* (Only the game instance that holds authority of this node (`Node.set_multiplayer_authority(id)`) calls this. Usually the server)
- *"any_peer"* (Self explanatory, every peer runs the function)

`sync` defines whether it also calls on the peer that sent the RPC. Options:
- *"call_remote"* (Doesn't run locally)
- *"call_local"* (Runs locally. Easy stuff, moving on. Chariots chariots chariots)

`transfer_mode` determines the protocal used to send the packet. Options:
- *"unreliable"* (Packets arrive (or not) in a random order at a random time. It can update stuff like positions faster though, so it's useful for positions, velocities, inputs, etc)
- *"unreliable_ordered"* (Packets arrive (or not) in order. Just a better version of the last one)
- *"reliable"* (Packets are slower but always arrive. For damage hits, lobby actions, events like game start, etc)

I don't care for `transfer_channel`. Bye.
